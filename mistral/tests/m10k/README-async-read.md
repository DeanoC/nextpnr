# M10K asynchronous read ports

The Mistral M10K BEL can expose the read address and data path without a read
clock or user read-enable. The nextpnr contract is an ordinary
`MISTRAL_M10K` cell with `CFG_ABITS` and `CFG_DBITS`, a write port on
`CLK1`/`A1*`, and a combinational read port on `B1ADDR`/`B1DATA`. `CLK2` must
be absent at the JSON boundary. `CFG_ASYNC_READ=1` makes the mode explicit
for primitive JSON generated by a future Yosys mapper; an omitted `B1EN`
selects the same mode so the backend can consume the `clocks 1 0` form used by
the memory mapper. An explicit B1EN is accepted only when it is tied high.

The packer leaves the read group on the existing M10K address and output BEL
pins, and does not create a TCLK route. A flow-through simple-dual `rden_b=1`
is represented by an omitted B1EN port; nextpnr keeps that logical contract
but materialises a constant-high internal B1EN connection to physical
`ENABLE[0]`. This avoids relying on a site-dependent power-up default: the
same omitted-enable image read as zero at M10K.026.001 until the explicit
enable route was added, while the routed image reads its initialized data.
An explicit constant-high B1EN is accepted and uses the same route. A
connected dynamic or low read enable, second clock or active ACLR is rejected
because each selects a synchronous read configuration. The shared write/read
clock is fanned out to both physical `CLKIN` sinks, and the bitstream selects
the bottom core/input clock tree plus the second-half core/input/output muxes
for the flow-through path. Constant-high byte enables stay on the M10K
default source; `CFG_BYTE_ENABLE` remains enabled, but no fabric route is
emitted for those constants. A dynamic or low byte mask still routes through
`BYTEENABLEA`. No Mistral geometry or physical table changes are needed.

Timing classifies `B1ADDR` as a combinational input and `B1DATA` as a
combinational output. Since Mistral has no characterized Cyclone V M10K
address-to-data arc, the host timing model uses a conservative 1.5 ns estimate;
it is not a silicon characterization. The estimate is visible when the read
result is captured by a fabric register.

The portable host regression synthesizes a direct primitive, edits it into the
future mapper's JSON shape, checks malformed controls, emits a compressed RBF,
decodes the M10K settings (including the explicit constant-high enable and
byte-enable defaults), checks a mixed dynamic/low byte mask, checks an
explicit-high primitive spelling, and checks the 50 MHz report:

```sh
python3 mistral/tests/m10k/async_read.py \
  --yosys /path/to/yosys --nextpnr /path/to/nextpnr-mistral \
  --mistral-cv /path/to/mistral-cv \
  --qsf /path/to/pins.qsf --sdc /path/to/clocks.sdc \
  --output /tmp/m10k-async-read
```

The locked Yosys tree still describes M10K inference with `clocks 1 1`, so
this nextpnr change does not alter Yosys or `toolchain.lock`. A follow-up
Yosys mapper change can emit the same cell shape without another backend
change. The regression is host-only and does not establish hardware behavior.
