# Guarded Boolean LUT timing profile

`--mistral-lut-core-reference` selects fitted Boolean LUT reference intervals
for `5CSEBA6U23I7`. It is an experimental, default-off profile for diagnostic
comparisons. It changes neither LUT packing nor clock constraints. Carry,
memory and all other cell models retain their existing behavior.

The public profile selects **slow 100 C**, matching the native routing, FF
and GPIO profiles. The retained corpus has four corners, but selecting this
flag does not enable fast-corner hold qualification. Fitted observations
are not general silicon bounds for every truth table, slew or load; positive
slack with this flag is not whole-board or hardware acceptance.

The generated table combines all valid input/output transition intervals
for each physical input, keeping rising and falling input envelopes separate.
It retains independent early and late values and rounds each envelope
outward by one picosecond. The table distinguishes LAB/MLAB, native L5/L6
mode, ALM position and half. Before configuration, placement uses the union
of every legal reference class for the known geometry. After configuration,
the actual CRAM selectors choose the physical mode.

Final timing requires a driven, net-owned native GOUT input and its complete
analogue input-buffer observation. The reference interval starts after that
buffer and ends at COMBOUT. STA charges the buffer once in the cell delay,
subtracting the same observation from the routed delay. Missing ownership,
pin identity, mode coverage or analogue observations stop the run. Feedback,
RAM and arithmetic modes are outside the profile. Explicit inactive constant
inputs do not create routed timing paths.

The current native source-wave API has no M10K data-output or FPLL lock-output
waveform implementation. A design with those sources feeding LUTs therefore
stops at the required analogue observation. This profile does not substitute
another source family's ramp or retain an estimated input-buffer delay on
those paths. Source-wave characterization is a separate prerequisite for
timing such designs with this flag.

Checkpoints record the selection and require the explicit flag again on
reload. Critical-cohort calibration records bind both the selection and the
reference data digest, so measured models cannot cross profiles. Ordinary
callers do not intern the new setting or alter their calibration identity.

Run the focused checks with a test-enabled Mistral build:

```sh
cmake --build build --target nextpnr-mistral nextpnr-mistral-test
./build/nextpnr-mistral-test \
  --gtest_filter='LutCoreTimingTest.*:CriticalCohort.MeasuredModelBindsLutReferenceModeAndData'
ctest --test-dir build -R '^nextpnr-mistral-lut-core-' --output-on-failure
```

`lut_model_reference.py --check` regenerates the table from the independently
validated reference corpus and rejects incomplete physical coverage or stale
generated bytes. The reference parser and decoder checks remain required
for updates to that corpus.
