What changed physically

Default and arrival-only seed-10 outputs have exactly the same 10,877
cell placements. 2,039 saved cell pin maps differ; the arrival log reports
5,339 input mappings changed. The ensuing data routes differ as expected.
The option's gain is therefore input assignment and its resulting routes,
not a different placement or an alternative timing model.

In the historical reference's limiting cone, the new arrival build maps
three ALUT5.E inputs from physical A to F, two ALUT4.D inputs from B to F,
an ALUT2.B from E1 to F1, an ALUT2.A from D to F0 and an ALUT3.C from E0
to F1. One other ALUT5.B becomes slower, E1 to B, showing why latest-arrival
selection is more specific than blindly favoring every logical last input.
The historical generated route-through buffer has no same-named cell in the new output. See reference-cone-pins.txt.

The fresh arrival seed-10 worst half-cycle path now ends on iff2.ENA.
It has 2.357 ns of LUT logic and 6.042 ns routing, total 8.868 ns including
clock/setup terms, against 9.574 ns. Its changed cone still has ten LUT
stages. Seven inputs use F, two use B and one D. The previously frozen
pin allocation is not carried into this producer rebuild.

Independent Quartus check of arrival seed 10

Quartus 17.0.2 Build 602 on Powerboat compiled the held-route replica in
quartus-arrival-s10/. All ten decoded rnode chains match the new original
path exactly. The path-input pins and LUT/launch FF sites also match.
As with the original investigation, this is a data-path replica: it uses
inverter LUTs, drops original side branches, replaces the final capture
with a nearby data FF, and retains nextpnr clock/skew/setup terms for the
full-path estimate. It is not full-shell TimeQuest signoff.

Q to last LUT output, ns:
  original nextpnr:             7.559
  Quartus replica slow 100 C:   8.574
  Quartus replica slow -40 C:   8.321

The replica's Mistral route-only sum is 5.093 ns. Including the ten block-
input stages makes it 6.329 ns; Quartus interconnect is 6.309 ns. Mistral
LUT cell delays sum to 2.357 ns; Quartus sums to 2.265 ns. The 1.2356 ns
of omitted terminal block-input stages dominates the discrepancy.

After original side-branch loading and final-hop correction, retaining
nextpnr clock/endpoint terms, the estimates are:
  slow 100 C: 9.998 ns, 50.01 MHz, approximately -0.424 ns slack
  slow -40 C: 9.625 ns, 51.95 MHz, approximately -0.051 ns slack
The uncertainty absent from this estimate would not improve setup margin.

fullpath.py initially found two final-hop candidates because unrelated
routes can have equal delays in the same tile. The final route was selected
by also matching its driving physical LUT site: LAB.022.009.5:FFB1 to
MLAB.015.009:DATAIN.2. This is the physical control-mux route to logical
iff2.ENA. Both original TSV variants and the selected result are retained;
this disambiguates the evidence without altering any timed design.

Next fix, based on the measured residual

1. Preserve #218's fast-pin legalisation and the current physical-pin timer.
   Latest producer builds recover nextpnr timing closure; retiming only the
   old sealed artifact cannot change its hardware.
2. Fix Mistral's missing GOUT-to-ALM input stage in routed LUT arcs.
   analogue_arc_delay currently stops when the native destination GOUT is
   reached, while FF/control endpoints use a nextpnr-created destination
   and already simulate the terminal stage. Append the LUT sink's terminal
   circuit with the propagated waveform, and charge it exactly once.
   Scope this by the actual LUT input endpoint, not merely all GOUT nodes;
   FF/control, carry and hard-block arcs need separate admission rules.
3. Make the routing-table and placement views price that same endpoint
   stage, so optimization does not chase a path the signoff model calls
   fast for the wrong reason. Do not double-count it on existing synthetic
   FF sink arcs. getWireDelay currently returns zero; any implementation
   using wire costs must account for shared native endpoints explicitly.
4. Add an exact-route regression using these retained Quartus path points:
   terminal stage included for LUT sinks, already-covered FF sinks unchanged,
   all ten chains preserved, and model agreement checked against the actual
   TimeQuest interconnect-plus-LUT totals. Recheck setup AND hold after the
   change; an added maximum must not manufacture early-delay margin.
5. Rebuild this same fixture with the corrected endpoint model and arrival
   profile on seeds 1,3,10. Judge closure under that corrected model and
   re-run the Quartus comparison before selecting a replacement shell.
   This is the next useful nextpnr implementation task. RTL retiming is not
   justified until that optimization/signoff mismatch has been addressed.

No C++ implementation fix is claimed in this experiment. The measurements
