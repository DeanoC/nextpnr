Regression mechanism, follow-up to the initial #236 investigation

The initial investigation established the failure, but did not sufficiently
separate a model-only loss from worse placement/routing or test a fresh
producer build. Option tests against a frozen scaffold cannot measure the
benefit of those options during shell production.

The same physical critical path, holding routes, pins, clock-to-Q, setup and
skew fixed, has these LUT maximum-delay charges (ps):

Pre-#172 charges come directly from d869795b^:mistral/delay.cc.
Current charges and physical pins come from the original routed checkpoint's
FES_PINMAP_V1 and final analogue report. This is a re-cost of identical
hardware, not an old-vs-new full-build benchmark.

The resulting path totals are 8.779 ns (56.95 MHz) and 10.941 ns (45.70 MHz).
The complete 11.25 MHz difference on this path can therefore be explained
without any new routing regression: the old logical-position model hid
2.162 ns of LUT delay. The Quartus identical-data-route replica supports
the current physical-model conclusion rather than the historical pass.

Physical cause: synthesis puts the important input last because its ALUT
model calls that input fastest. The old ALM legalizer could assign that
logical input to slow physical A/B instead of F. The old timer still charged
97 ps, regardless of the physical assignment. #172 (d869795b) corrected
the reporting; #218 (552ba246) subsequently changed fresh legalisation
to put the last private L5 input on F and to keep eligible shared critical
inputs private. It also corrected placement's estimate for that last input.
The frozen shell still contains the historical A/B assignments, so loading
it with latest nextpnr preserves the defect in the artifact.
