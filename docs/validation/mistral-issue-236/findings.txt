Conclusion

The sealed ZX81 1.5.0 shell fails timing under latest nextpnr main
e904cbfbf18c4218f03a9e1e121d19ada0bbdaf4 without a cart or routing.
The matching Quartus data-path replica supports a real timing miss, rather
than a pessimistic nextpnr LUT/data-route model. This is not full-shell
TimeQuest signoff and does not establish silicon failure.

Why exit 0 and why options cannot fix the published package

scaffold.json contains timing/allowFail=1. The setting survives reload;
omitting --timing-allow-fail does not remove it. The final timing logger
therefore emits a warning and the command returns success. Removing the
inherited setting makes the same analogue miss an error and exit 1.
Report-only analysis deliberately calls timing_analysis without failure
enforcement, so its exit 0 is not a signoff verdict either.

fes_slot.cc locks shell cells and routes at STRENGTH_LOCKED and restores
their physical pin maps. Seeds, congestion spreading, timing weights,
router choice and analogue-repair budgets cannot change this shell cone.
lab.cc excludes locked cells from arrival-pin reassignment; critical-cohort
repair rejects them. Local/comb remapping explicitly rejects slot-active
designs. These options belong in a fresh shell build before sealing.
Never unlock or modify the published package to try them.

The retained quartus/ project compiles successfully. It preserves the

Launch Q to last LUT output:
  nextpnr original loaded route: 9.828 ns
  Quartus replica slow 100 C:   10.191 ns
  Quartus replica slow -40 C:   10.004 ns

Replacing that part of the original timing path with Quartus delays,
adding Mistral's removed-side-branch loading difference and original final
hop, and retaining nextpnr skew/clock-to-Q/setup, gives estimates:
  slow 100 C: 11.541 ns, 43.32 MHz
  slow -40 C: 11.224 ns, 44.55 MHz
See quartus/fullpath.txt. The original final control route decodes as
LAB.004.001:DATAIN.2; this is the physical control-mux input route, while
the timed logical endpoint remains FF ENA.

Limits: the replica uses inverter LUTs, drops original side branches,
launches on posedge, and replaces the final hop/capture with a nearby data
FF. It cross-checks the eight data hops, not the original clock tree, duty
cycle, launch polarity or capture ENA timing. The full-path estimates use
nextpnr terms for those omitted pieces and omit Quartus uncertainty.
They must not be described as a full-shell TimeQuest Fmax measurement.
Original-route cell-arc re-costing also predicts failure (42.21 MHz at
100 C), but the actual identical-route replica is stronger evidence.

The earlier logical-position LUT timer would assign this same frozen
path 56.95 MHz (fullpath.py calculation). That explains how historical
optimism could hide the miss; it does not prove how this shell was qualified
or equate that calculation with the issue's 56.63 MHz placement estimate.

Fix plan, in order

1. Make strict final analogue shell acceptance explicit in its producer.
   Reject inherited timing/allowFail and require exit success, all clock
   targets met, setup/hold WNS nonnegative, final_analogue_model=true, and
   the existing seal/CRAM checks. A written RBF alone is insufficient.
   Treat report-only output as diagnostic. Check every published shell;
   do not silently reinterpret historical allowed failures as passes.
   Decide separately whether nextpnr should refuse RBF publication after
   failed strict signoff; currently it writes the file even with exit 1.

2. Rebuild from the shell's pre-seal synthesis/placement inputs with latest
   nextpnr and unchanged clock/slot/CRAM constraints. Record hashes. Compare
   a small fixed seed set (1-4) for default, isolated-lut-placement,
   arrival-pin-assignment, then both; keep router2/fallback and GPU-reference
   cohorts separate. Route GPU jobs only through gpu-run. Judge final
   analogue timing, every clock's setup/hold and seal validity, not placement
   estimates. No extra vendor run is required.

3. If those builds miss, use pre-seal routed reports to target the whole CPU
   cohort: critical-cohort placement (--critical-cohort-budget with prior
   analogue guidance), legal arrival-driven pin assignment and bounded
   local/comb/LUT-pair remapping where their eligibility rules permit.
   Target long inter-LAB hops and the A/B-pin stages of the ce_3m25 -> bus ->
   decode -> group_sel enable chain, as well as the failing full-cycle CPU
   paths. Never assume each critical input can legally occupy F: shared
   ALM pins and other consumers constrain the assignment. Seek positive
   margin beyond the 1.367 ns half-cycle deficit and -1.608 ns overall WNS.

4. If physical optimization is insufficient, change the shell RTL: factor
   the bus/decode enable cone or precompute decode terms from registered
   state before the falling-edge launch. Move/register the enable only
   after proving the CPU bus cycle and interrupt semantics. This is a shell
   rebuild with functional verification, not a cart patch or an automatic
   negedge-to-posedge conversion. Do not add an unproven multicycle or
   false-path exception and do not lower the required clock.

5. Before release, cross-check the candidate's original launch/capture/ENA
   edges and clock waveform in TimeQuest, including both slow corners and
   hold. Extend the replica or export the full shell for clock/endpoint
   coverage. Repeat strict analogue signoff on the sealed shell, then the
   ram16k cart seeds 1-4 with unchanged seals and timing checks. Run board
   validation only with a claimed kit and restore/release its baseline.
   Publish a new shell package; the existing immutable package cannot be
   repaired by cart-routing options.

checkpoint aborts in compute_analogue_arcs -> analogue_arc_delay ->
getBelPinsForCellPin, dict<IdString,ArchPinInfo>::at. Adding the original

specific missing cell/port was not isolated. This is a separate replay follow-up, not a
timing fix or a successful latest cart run. No source changes were made
to work around it. The latest no-cart analogue run completed successfully
and reproduces the issue independently; the Quartus comparison uses the
retained original cart RBF and report, not the failed replay.
