Terminal LUT-input timing correction for issue #236
2026-10-20, base nextpnr e904cbfb

Implemented

The native wire used as a Boolean LUT input ends at GOUT, before its
block-input mux. The old analogue arc stopped there and getCellDelay
charged only the physical LUT mux levels. The terminal stage was absent
from both terms. Synthetic FF/control endpoints already include it.

delay.cc now simulates the terminal GOUT circuit using the propagated
input waveform for ordinary ALUT2-6, BUF and NOT inputs. Both rise/fall
and early/late results are retained. The existing graph boundary stays
at GOUT: getCellDelay adds the measured terminal input term, and the
routed override removes that same term from the full analogue arc.
The sum counts the circuit once. Graph topology, pin maps, routing
constraints, bitstream generation and frozen-shell locks are unchanged.

Before an analogue observation exists, the cell-input stage uses the
existing GOUT table's 175 ps late estimate. The early estimate is zero,
so placement/routing cannot invent hold margin from an unmeasured mux.
The cell-side charge makes the corrected budget visible to placement,
pin assignment and every router's timing analysis, including the GPU
router's internal table-based arc updates.

The analogue cache retains the complete routed observation and its
terminal component. Candidate-route comparisons use full observations;
STA splits them at GOUT. Both initial computation and accepted candidate
updates preserve the terminal component. Existing per-net rip-up
invalidation drops it with the routed observation. Planning copies
cannot borrow the incumbent cell's cached input delay.

The terminal circuit is not a real routing pip. It is excluded from
pip-delay observations and type calibration, preventing calibration from
charging it again. Existing FF/control arcs, arithmetic and hard-block
timing are unchanged. This correction is specifically for the measured
ordinary Boolean LUT input boundary, not a new characterization of the
entire device.
