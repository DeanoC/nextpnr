Why the pin change helps

The old optional heuristic ranked maximum absolute data arrival across
launch domains. The issue's half-cycle paths compete at LUTs with longer
full-cycle paths. A later absolute arrival can still have much more time
to reach capture, so that ranking can assign the fast pin to the wrong
input. This is distinct from the historical LUT timing undercount and the
missing terminal-input stage already investigated.

The heuristic now ranks by -setup_slack - current_cell_delay. Reassigning
an input to a new pin changes its slack by old_cell_delay - new_cell_delay.
Subtracting the current charge therefore removes incumbent pin speed from
the priority, while setup slack supplies the correct launch/capture clock
window and downstream deadline. Untimed inputs remain fixed. This retains
one timing snapshot and the existing opt-in flag; carry, LUT6, shared pins,
frozen cells and direct register input exclusions are unchanged.

The old seed-1 worst path starts at ce_3m25's falling edge, crosses ten
LUTs, and ends at iff1.ENA. Among its changes, the first LUT's critical
input moves E0 -> F0, and the next LUT's critical input moves B -> E1.
Those two raw LUT mux costs fall by 486 ps in total. Routing changes too.
All 10,852 cell names, types, parameters, logical connections and BELs
are identical between the two results; 115 cells' saved pin maps differ.
The transformed path ceases to be the worst path. See physical-diff.txt.

Independent Quartus check of the passing seed

Quartus Prime Lite 17.0.2 Build 602 on Powerboat reconstructs two critical
data cones from the seed-1 RBF. All original programmable route chains,
physical destination pins and sites are preserved in the decoded replica
bitstreams. The full-cycle replica also preserves the four consecutive
arithmetic sites and all three dedicated carry connections.

Full-cycle bottleneck, ending at halted.ENA:

  nextpnr Q -> last logic output:            17.279 ns

Worst half-cycle bottleneck, ending at video.fb.0.122.A1EN:
  3 Boolean LUTs and 3 exact programmable data routes
  nextpnr Q -> last LUT output:               3.774 ns
  Quartus same data cone at 100 C:            3.513 ns
  Mistral correction for removed branches:    0.191 ns
  full path after data substitution:          9.110 ns, 54.88 MHz
  same estimate at -40 C:                     8.429 ns, 59.32 MHz

The full-path estimates retain nextpnr's launch clock-to-Q, skew and setup;
use Mistral's final sink hop including its terminal stage at each corner;
and add the Mistral difference for original side-branch loading. They do
not add Quartus-derived uncertainty. These are independent data-cone
cross-checks, not full-shell TimeQuest or hardware signoff.

The carry replica includes two preceding arithmetic cells in ALM 0 so
Quartus can place the original critical carry section starting in ALM 1.
That prefix drives a side input of the first critical arithmetic cell;
it is outside the timed q0 cone. Non-shared arithmetic sharein is left
unconnected. Ordinary replica LUTs are inverters; carry truth tables
sensitize B -> CO, CI -> CO and CI -> SO. Original side consumers are
omitted as in the existing replica method. The retained top.v/QSF/RCF/SDC
and decoded route chains document the final successful projects. Earlier
scratch-only replica construction failures were not accepted as evidence.
