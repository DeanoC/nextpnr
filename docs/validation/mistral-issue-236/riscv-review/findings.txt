Fresh-report versus checkpoint replay

The fresh actual-base result is 66.462852 MHz, while its checkpoint replay
at that same base gives 68.245415 MHz. The fresh PR result is 60.628109 MHz,
while its same-RBF replay gives 63.343258 MHz. Neither replay replaces the
original final signoff result or qualifies a package.

The first PR critical arc, system.cpu.rs2[6], is not in the successful
analogue-arc dump (82139 completed hop rows). It therefore retains the
router's delay-table fallback. Its fresh charged routing delay is 2.115 ns;
the replay is 1.408 ns, exactly the 0.707 ns difference between those critical
periods. The cell charge remains 0.758 ns, including the conservative
175 ps input estimate. Route-time pip observations/type calibration are
not restored from routed.json, so those fallback numbers differ despite
identical hardware. This is not evidence that the route physically sped up.
The fresh base exhibits the same class of discrepancy before this PR.
See fallback-diagnostic.json and the retained full reports/arc dump.
Do not disable calibration or use the more optimistic replay as signoff.

Remaining fix plan and scope

1. Keep #267's correction and the ZX81 producer evidence explicit. The
   original five failing unit tests were fixed in 6bf1ae66; its four Mistral
   shards pass 372 tests with one expected snapshot skip. All 16 architecture
   CI checks at that implementation head pass. This follow-up adds evidence,
   not a timing-model relaxation or another core's recipe/RTL change.
2. Investigate RISC-V closure separately from issue #236. The fresh base's
   bottleneck launches at the M10K register file and reaches CSR registers
   (including minstret), with ALU logic between them. The source suggests
   branch/trap/retirement selection as the control cone to trace next.
   The PR's seed-1 worst path also contains a long arithmetic carry chain.
   Earlier arrival-pin/isolation/placement experiments already failed to
   close it. More blind seed rerolls are not the next step.
3. A focused RISC-V change should first shorten late branch/trap/retirement
   control and CSR write selection, or register the late decision in a
   separate execution phase if same-cycle restructuring is insufficient.
   Confirm the path by following report cell/port connections; Yosys names
   that contain csr.wdata are not proof that every path is CSR operand data.
   Preserve instruction results, traps, interrupt priority, and counter/
   retirement semantics. Such a core change belongs in a separate FES issue
   and PR, with CPU/CSR semantic tests and the RISC-V simulation.
4. Rebuild that core with the corrected compiler, fresh identities, unchanged
   clocks and strict setup/hold gates. Require a declared three-seed candidate
   comparison, normal full producer/seal qualification and exact-artifact
   hardware acceptance before promoting its pin/profile. Preserve the
   current RISC-V pin until that work qualifies. Do not bundle it into ZX81.
5. The RISC-V timing gate remains open for review. The evidence corrects the
   regression attribution; it does not authorize merging, hide the smaller
   route loss, relax a constraint, or change any factory selection.
